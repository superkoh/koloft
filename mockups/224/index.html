#224 - a session's listening ports, in the Workbench "+" menu

The "+" button at the right of the Workbench tab strip already opens a small menu (New web tab / Open file… / New terminal). The change adds one section under a separator: the ports that the processes of this session are listening on. Clicking a port opens http://localhost:<port> in a new web tab of this session, the same way "New web tab" + typing an address does. Nothing opens by itself: the list is scanned when the menu opens, and a page opens only on the person's click.

The head row uses the menu's existing .mi.head style (mono, faint, not clickable). A remote (ssh) session's menu shows no ports section at all until #431 gives it a way to reach a remote port.

What a click does

  • A port row calls the same path as typing an address into a new web tab: openHere({ kind: 'web', url: 'http://localhost:5173', source: 'user' }), then applyLive. The tab belongs to this session's Workbench like any web tab the person opened.
  • The menu closes, as it does for the other three rows.

When the scan runs

  • Only when the "+" menu opens: one ps -Ao pid=,ppid=,command= to walk the session's process tree from its root pid, and one lsof -a -p <tree pids> -iTCP -sTCP:LISTEN -Fn for the ports. Measured on this Mac: about 30 ms each. No timer, no new background scan, nothing stored.
  • The rows appear a moment after the menu opens; until then only the three usual rows show. Ports are de-duplicated (a server bound on IPv4 and IPv6 is one row) and sorted.

The four kinds of session tab

  • Claude Code, local - root pid is the pty's process, which is claude itself (Koloft spawns it directly). Same as shown above.
  • Codex, local - root pid is this tab's own codex app-server (one per tab, not shared; the TUI in the pty runs no commands). Same menu, same rows.
  • Claude Code, remote (ssh) - left out: the processes live on the other machine, so even a found port needs an ssh forward to open (#431, still at its probe step). The menu shows no ports section.
  • Codex, remote - does not exist yet (#99).
