#758 · A folder you add shows its past sessions in the middle panel

Today: you add a folder you already worked in, and the app shows nothing about that work. After: the middle panel lists it, one click to carry on.

Every frame below is the real app's page and stylesheet, captured from a build of main; only the middle panel (and, in option B, the sidebar rows) was changed by hand. Words in the frames are the app's own English.

What is still broken

The welcome's own path is already fixed: since the new welcome, the folders it pins bring their last sessions into the sidebar (test T-OB-02). What is left is every folder added by hand (⇧⌘O, the folder button, a remote directory): the sidebar and the panel stay empty, and the past sessions sit behind the folder menu's "Restore session…". A probe on main shows it (notes/758/probe-758.spec.ts).

Option A · list them in the panel suggested

Under the buttons, a "Past sessions" block: the newest three sessions of this folder that are not in the sidebar, each with its branch and age, as the Restore dialog words them. Clicking one does what the dialog does: the session resumes and its row joins the sidebar. With more than three, a last row opens the Restore dialog with all of them. The sidebar stays as it is. It shows for every folder with such sessions, old or new.

Option B · adding a folder brings its last sessions into the sidebar

No new block. Adding a folder by hand does what the welcome does: up to four sessions from the last two weeks become grey rows in the sidebar, and today's "Recent" block lists them. Older sessions stay behind "Restore session…". Folders that are already pinned do not change.

Option C · one button with the count

Under the buttons, "Restore session… · 3 past sessions", which opens the dialog that exists today. The smallest change; the sessions' names are still one click away.

What each kind of folder and agent does (options A and C)

The block reads the same list the Restore dialog reads, so the two always agree. The panel and its buttons show at once; the block fills in when the list answers.

Claude Code From its transcript files, already read: shows at once. From the copy of the machine's transcripts kept on this Mac: shows at once, also while the machine is off line (the last copy). Never connected yet: nothing until the first copy arrives.
Codex Asks the local Codex for its thread list each time the panel shows. Asks Codex on the machine over SSH (answer kept 15 s, gives up after 10 s). Machine out of reach: no Codex rows, no error.
Muse Asks the local Muse for its session list each time the panel shows. Listed from the machines connected at that moment. Not connected: the list from earlier in this run, none after a restart.
Antigravity Reads its local conversation files each time the panel shows. Same as Muse.

Run and seen: Claude Code on this Mac (the probe). The other seven cells are read from the code and from the existing Restore tests, not yet run for this panel. Option B on a remote folder is not probed yet: at the moment of adding, the machine is usually not connected, so there is nothing to bring in until later.

After an upgrade

A and C: every pinned folder that has sessions behind "Restore session…" starts showing the block or the button in its empty panel, including sessions the user took off the list by hand. Nothing moves in the sidebar, nothing is lost. B: nothing changes for folders already pinned.
