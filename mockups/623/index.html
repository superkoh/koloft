Removing a git account kept on a machine Koloft cannot reach (issue #623)

Who and when: a user has a git account on a remote machine (Settings ▸ Accounts ▸ Git accounts, machine devbox) and removes it while devbox is asleep or the VPN is down.

Today: the row disappears at once and nothing looks wrong. On devbox the token file, the account's helper script and the pick that points at it all stay. When devbox is back, Koloft sessions there still send the removed account's token. The next change on devbox clears the helper and the pick, but the token file itself is never deleted.

 click Remove ──► ssh devbox "delete token"  ✗ (machine down, result ignored)
              ──► drop account from the Mac's list  ✓
              ──► ssh devbox "rewrite config"     ✗ (ignored)
 row is gone; token, helper and pick stay on devbox

The two choices

A. Refuse while the machine is out of reach (recommended)B. Remember it and finish later
What the user seesThe row waits ("Removing…"; Koloft stops at the first failed try, at most 10 s on a machine that does not answer), then says Koloft could not reach devbox and the account is still there. Buttons: Try again, Remove from list anyway, Cancel.The row disappears at once, as today. Nothing tells the user the token is still on devbox.
What is storedNothing new.A "remove this from devbox" note in Koloft's settings, kept until it is done. (A cheaper way: no note at all, and every later update of devbox also deletes token files no account owns.)
If devbox never comes back"Remove from list anyway" drops it from Koloft only. Should devbox come back after all, the account keeps working there until Koloft next updates devbox, and its token file stays.The note stays in settings forever, unseen.
When devbox is backNothing pending; the user clicks Remove again (or already chose "anyway").Koloft does run things on devbox today (opening a tab, finding repositories), but none of them would run the removal: it needs a new trigger. Until it runs, sessions on devbox still send the token.

Every kind of session tab

Claude Code, Codex, Muse Code and Antigravity tabs on devbox all read the same git setup there, so each option behaves the same for all four. Local tabs are not touched: an account on this Mac is removed from this Mac's own keychain, which is never out of reach. The only screen that changes is Settings ▸ Accounts ▸ Git accounts, and only for option A.
