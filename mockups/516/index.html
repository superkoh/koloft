#516 - how many helpers run inside a session, on its row

In short: the session row already has a "still running in the background" badge, ↻ N, and background helpers (subagents, workflows, Codex sub-agents) are counted in it. The choice is whether that is enough (close the issue) or whether to go one step further.

Rows and the card below are the real app's DOM, captured from a built app driven by the e2e fake claude, and drawn with the app's compiled CSS. Only the rows marked "option" are made up.

The row has the "working" colour but no number. A background helper started in this turn joins ↻ N only when the turn ends. A foreground helper (the session waits for it) is never counted, not even after the turn. A helper left over from an earlier turn keeps its ↻ N while the next turn works (the card heading then reads "Background activity"), and if it finishes mid-turn the badge only drops at the turn's end. 3. The options

A. Keep it as it is, close the issue pick

No code. The issue's goal, telling a session busy with helpers from an idle one, is met at turn end for all eight tab kinds by ↻ N; while a turn runs, the row already has the "working" colour.

Cost: no number while a Claude Code turn runs; Claude Code foreground helpers are never counted; Antigravity shows no count (and none at all next to a named background command); ↻ N adds helpers, commands and working teammates together.

B. Claude Code: background helpers show as soon as they start

Fake session: project notes
main
Started a helper: Review the tests

Option. Like Codex and Muse Code today. Koloft already reads the "spawned in the background" line from the transcript mid-turn; it just does not put it on the row until Stop. A helper that finishes mid-turn would also drop at once.

Cost: background helpers only; foreground ones still never show. A Workflow joins mid-turn only if its spawn line carries an agent id (its shape is in the ledger, the id is not probed). Antigravity unchanged. The badge text does not change, so few e2e cases move.

C. Claude Code: every helper that is writing, foreground too

Fake session: project notes
main
Started a helper: Fix the parser

Option. Count each helper whose own transcript file grew in the last few seconds. Koloft already reads those files every 5 seconds (for usage), so no new polling.

Cost: "running" means "wrote lately": a helper waiting on one long command writes nothing and drops out of the count until it writes again. A cloud helper has no local file and is not seen. Antigravity unchanged.

D. Add-on to B or C: say "helpers" apart from commands

Option. The badge says how many of the running things are helpers.

Cost: a longer badge leaves less room for the title in a narrow sidebar. The text is built in one place for all four agents, but the e2e helper that looks for exactly ↻ 1 and the specs using it change.

4. Not probed yet

  • Codex and Muse Code over SSH: the code is the same as local; no e2e case runs a helper there.
  • Antigravity, a count: each helper is a child row (with a parent id) in its conversation database, which Koloft reads today only for rows without a parent; a SessionStart hook fires for each helper (ledger), but its other hooks for helpers are not probed.
  • Claude Code: whether a Workflow's spawn line carries an agent id (matters for B only).
