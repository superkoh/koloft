Say why the worktree could not be rebuilt

When you resume a session whose worktree was deleted, Koloft tries to make the worktree again. If that fails, the "Could not rebuild the worktree" dialog opens. Today it never says why. After this change, it shows one more box with the reason.

Where the reason comes from, for each kind of session tab

Tab How the reason is taken What the box shows
Claude Code, this Mac rebuildWorktree (src/main/backends/claude.ts) keeps the stderr of its failing git worktree add. hostGit() passes git's onFailure on, which localGitOut already supports. git's error line(s).
Claude Code, remote The same onFailure, which the SSH host's runGit already calls with git's stderr from the machine. git's error line(s); if the SSH link broke, ssh's own error.
Codex, Muse Code, Antigravity — this Mac resumeRun (src/main/storedSessions.ts) keeps the error it catches today and throws away. A git failure there carries stderr; Koloft's own checks throw a plain sentence. Koloft's sentence ("The missing worktree is locked; unlock it before rebuilding", "The recorded repository has changed", …) or git's error line(s).
Codex, Muse Code, Antigravity — remote The same catch. The remote git call (machineTreeIo) already throws an error whose message is git's stderr. Same as on this Mac.

The reason is taken from the error itself, not from the worktree record: when a worktree that Koloft never recorded fails, the record is deleted again, and some failures happen before any record is written.

When there is no reason

The dialog looks exactly as it does today (no box). That happens when git timed out with no output, and in three Claude Code cases that fail before git runs: the worktree path is not under .claude/worktrees, the branch name is not one Koloft passes to git, or the rebuild plan changed between the click and the resume.

How the text is trimmed

  • git prints a progress line first ("Preparing worktree (checking out …)"); everything before the first fatal: or error: line is dropped.
  • A local git failure in Node also says "Command failed: git -C <path> worktree add …"; the stored agents use the error's stderr, so that line never shows.
  • Long text is cut at 400 characters. Paths are kept.

Both ways into the dialog

The dialog opens from a resume click (runResume in resumeFlow.ts) and from restarting a tab (store.ts). Both pass the result's reason on.
