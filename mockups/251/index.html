#251 - a "viewed" check for each file in the Changes view

Each file's header row gets a "✓ Viewed" button. One click folds that file's diff, puts a check on its row in the file list, and adds "1 viewed" to the total at the top. A second click undoes it. The check is still there after Koloft restarts. When the file changes again, the check goes by itself and the diff opens again.
  1. Not viewed (src/parser.ts below): as today, the diff is open.
  2. Viewed (src/cli.ts): "✓ Viewed" is lit, the body is folded to the header row, and its list row has a check.
  3. Viewed, then changed again (README.md): the check is gone and the diff is open again, so it looks like ①. The orange tag only points it out here; the app has no such tag.
How "changed again" is told: on marking, Koloft keeps a fingerprint (hash) of that file's diff text; when the current diff text differs, the file counts as changed. Kept in this Mac's localStorage, per workspace folder, apart from the open/folded state.
The choice for you: Koloft reads a file's diff again only when its +/− counts or status letter change, on "Reload", or on a base switch. So an edit that keeps the counts (one word changed inside a line that was already added) leaves the check on until "Reload". Pick: accept that (no code). The other way: on every folder change, read each checked file's diff again (on a remote workspace, one more ssh call per checked file each time).
On a viewed file the "Diff" / "Source" buttons are greyed (the body is folded, so they would do nothing); "↗ New tab" still works.
No new CSS class: the button is the existing .seg, the list check is the existing .bv-bm, and folding renders no body. Only this note, the frame and the orange tag have styles of their own.
