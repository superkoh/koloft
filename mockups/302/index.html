#302 — "No changes" while the session wrote files outside the folder

Built from the real app: the Workbench panel's DOM and the compiled CSS were captured from a test build (a session in a worktree fix-readme wrote README.md and src/main/index.ts into the main checkout ~/koloft). Only the text marked "after" was changed by hand. Paths are placeholders.

Rules

  • "Outside" = files the session wrote with its file tools, outside the folder the Workbench shows, minus anything under the session's scratchpad (it has its own section), Claude's tasks folder, agent-only files (memory, CLAUDE.md, skills — the same rule the Docs list uses) and files whose folder is gone. Capped at the 300 files a session keeps.
  • The tooltip on the button and the "N files · +a −r" line in Changes stay git's numbers.
  • The button adds " · N outside" only when N > 0. With git changes too: "3 files · 2 outside" (+/− counts stay git's).
  • The empty state reuses .fv-empty and the .cv-retry button of the Changes banner; the only new CSS is one rule stacking its lines (flex-direction: column; gap: 8px).
  • One function computes the list; Browse ▸ Outside, the button and the empty state all read it, so the numbers always match.

Per tab kind

Tab What it sees
Claude Code · local Same for Write / Edit / MultiEdit / NotebookEdit in the main conversation. A sub-agent's writes are not counted (Koloft reads sub-agent transcripts for usage only). A file that no longer exists drops out.
Claude Code · SSH As local; also a path written as ~/… is not counted (Koloft cannot resolve the remote home).
Codex · local / SSH Same. Patch writes, also the ones before a resume.
Muse · local / SSH Same for write_file / edit_file; writes made before a resume are not remembered.
Antigravity · local / SSH Same for write_to_file / replace_file_content; writes made before a resume are not remembered.
All eight A file written by a shell command (echo > f, sed -i, cp) is not counted: no agent reports its path.
All but local Claude A written file that was deleted later still counts while its folder exists.
The four SSH kinds Paths carry the machine name, so inside/outside works the same; read from code, no test covers Outside on SSH yet.
