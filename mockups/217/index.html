#217 — pick an element in a Workbench web tab and send it to the session

Built from the real app's DOM and compiled CSS (a dev build with a web tab open). The page inside the tab and the blue highlight are drawn by hand here: in the app, the page is the real site and the highlight is Chromium's own inspect overlay.

1. A new button in the web tab's address bar

Right after the address field, an icon button in the same style as the others (.bnav). The icon is a placeholder (the existing "location" pin): the real glyph is drawn new with the icon sheet rule once the plan is agreed.

2. Picking

The button turns orange (the same "on" look as the Outline button). Moving the mouse over the page outlines the element under it, with its tag and size. A click picks it and does not reach the page (measured: the page's own click handler did not run). Esc, the button again, or a click outside the page stops without sending.

3. Sent: it waits in the session's input box

The pick lands as one paste ("[Pasted text #1 +17 lines]") in the input box of the session this Workbench belongs to, not sent, and the keyboard focus moves there. No toast, like ✎ comment. You type what to change ("make this bigger") and press Enter — the same way a ✎ comment on a diff works today (#4).

  • HTML: the element's outer HTML, cut at about 4,000 characters with "… N more characters".
  • CSS: a fixed list of about 20 computed properties that decide how a thing looks and sits (box, spacing, border, colour, font, flex/grid, shadow, opacity) — not all ~480.
  • Picture: a PNG of just that element, saved to a file; the paste carries its path, and the agent opens it with its own file tool.

When the button is off

  • The session is not running, or is waiting on a permission question: the button is greyed, its tooltip says why (the same reasons as ✎ comment).
  • A blank tab or an error page: greyed.
  • An agent driving the same page does not grey it: the pick shares the agent's connection to the page, and the agent keeps working afterwards (measured with a real Playwright client in the built app).
